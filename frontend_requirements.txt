1. EXECUTIVE SUMMARY & ARCHITECTURAL FOUNDATION
================================================================================
The Family Health Guardian frontend is an enterprise-grade, consent-driven, 
role-aware healthcare web application. It connects family members, patients, 
and designated guardians in a single privacy-first portal.

Core Architectural Tenets:
1. Security Identity (auth.uid()):
   - Authentication is performed via Supabase Auth (Email/Password).
   - The frontend forwards the Bearer JWT on every API request.
   - The backend enforces auth.uid() directly on every database operation.
2. Zero-Trust Family Context & Consent:
   - The frontend never assumes permissions. Client-supplied family_member_id is 
     verified against ownership or active consent (READ_ONLY vs FULL_ACCESS).
   - UI elements (Edit, Delete, Add Schedule, Save ML Assessment) dynamically adapt
     based on the active user's permissions.
3. Private Medical Storage:
   - Report files are never stored in PostgreSQL as blobs; they reside in Supabase Storage.
   - Uploads go via POST /medical-reports; downloads render secure, signed URLs 
     with short 5-minute expiries.
4. Privacy-First Emergency SOS:
   - Location is captured ONLY during an explicit SOS trigger (3-second hold).
   - No continuous background tracking.
5. Dual-Engine Machine Learning & Clinical Explainability:
   - Two specialized Scikit-Learn Random Forest models:
     a) Diabetes Risk Classification (ROC-AUC ~0.83, positive recall prioritized).
     b) Hypertension Risk Classification (ROC-AUC ~0.76, positive recall prioritized).
   - Explainable AI: Per-patient local feature attribution (`feature_impacts`) highlighting
     individual risk drivers (HIGH_RISK_FACTOR, MODERATE_RISK_FACTOR, PROTECTIVE_FACTOR).
   - Longitudinal Risk Tracking: Trajectory calculation (IMPROVING, WORSENING, STABLE)
     across historical assessments with delta percentage analytics.
   - One-Click Prefill: Seamlessly pulls documented chronic conditions from health records
     and latest physical vitals from prediction history.
   - Automated Critical-Risk Alerts: High-confidence critical predictions (>= 75% diabetes,
     >= 70% hypertension) automatically trigger emergency notifications to family guardians.
6. Tamper-Evident Audit Trail:
   - All healthcare operations (view, create, update, delete, ML inference) are logged.
   - Passwords, tokens, and secrets are sanitized before persistence.

3. GLOBAL STATE & CONTEXT MANAGEMENT
================================================================================
The application requires 4 global providers:

1. AuthContext:
   - Stores current Supabase `user`, `session`, `accessToken`.
   - Handles login, signup, logout, session expiration refresh.
   - Profile state (`GET /profiles/me`).

2. FamilyContext:
   - `families`: List of families user belongs to (`GET /families`).
   - `activeFamily`: Currently selected family.
   - `activeFamilyMembers`: Members of active family (`GET /families/{id}`).
   - `selectedMemberId`: Target member currently being viewed/managed.
   - Role state: Whether current user is `ADMIN` or `MEMBER` in `activeFamily`.

3. ConsentContext:
   - Active permissions for the current user across family members (`READ_ONLY` vs `FULL_ACCESS`).
   - Determines visibility and disabled state of action buttons.

4. NotificationContext:
   - Unread badge counter (`GET /notifications?status=PENDING`).
   - Polling / Supabase Realtime channel for incoming alerts (Medicine reminders & SOS alerts).
   - Audio chime on critical high-risk health alerts.

5.14 Diabetes ML Risk Assessment (/predictions/diabetes)
--------------------------------------------------------------------------------
- Endpoints:
  * `GET /predictions/diabetes/metadata` (Public metadata and clinical ranges)
  * `POST /predictions/diabetes` (Protected inference, requires JWT Bearer)
- Biometric Form Inputs:
  * `age` (Number, 0 to 120, float)
  * `gender` (Enum: "Male" | "Female" | "Other")
  * `hypertension` (Boolean toggle)
  * `heart_disease` (Boolean toggle)
  * `smoking_history` (Enum: "never" | "current" | "former" | "ever" | "not current" | "No Info")
  * `bmi` (Number, 10.0 to 80.0, Body Mass Index with inline Height/Weight calculator helper)
  * `hba1c_level` (Number, 3.0 to 20.0%, normal < 5.7%, prediabetes 5.7 - 6.4%, diabetic >= 6.5%)
  * `blood_glucose_level` (Number, 30.0 to 600.0 mg/dL, normal fasting 70 - 99 mg/dL)
  * `family_id` (Optional string UUID)
  * `family_member_id` (Optional string UUID)
  * `save_to_records` (Boolean toggle: persist assessment in prediction history)
- Top Bar Actions:
  * "Auto-Prefill Measurements" button: Calls `GET /predictions/prefill/{family_member_id}` to populate existing conditions and recent measurements.
  * "Quick Preset" buttons:
    - Healthy Preset: 26yo, Female, BMI 21.8, HbA1c 4.8, glucose 88, non-smoker.
    - Borderline Preset: 48yo, Male, BMI 27.8, HbA1c 6.0, glucose 125, hypertension.
    - High Risk Preset: 65yo, Male, BMI 34.0, HbA1c 8.2, glucose 195, heart disease, hypertension.
- Results & Clinical Risk Panel:
  * Risk Badge: `Low Risk` (Green) vs `High Risk` (Rose/Red)
  * Risk Percentage Gauge (0.0% to 100.0%)
  * Confidence Level Meter: `High Confidence`, `Moderate Confidence`, `Low Confidence (Borderline)`
  * Biometric Feature Summary card reviewing input values
  * Feature Attribution & Explainability Panel (detailed in 5.16)
  * Dynamic, Rule-Based Clinical Recommendations list tailored to specific risk factors:
    - HbA1c diabetic threshold alerts (>= 6.5%)
    - Pre-diabetes dietary intervention advice (5.7% - 6.4%)
    - Fasting glucose monitoring advice (>= 140 mg/dL)
    - BMI nutritional & exercise guidance (Overweight >= 25, Obese >= 30)
    - Cardiovascular dual lipid/glycemic coordination alerts
    - Microvascular smoking cessation counseling
  * Automated Emergency Alert: If saved to records and risk >= 75%, banner displays:
    "Critical Risk Alert: An automated notification has been dispatched to family guardians."

8. FRONTEND SECURITY, VALIDATION & ERROR HANDLING
================================================================================
1. Client-Side Input Validation (Pre-Flight Checks):
   - Numerical Biometrics:
     * Age: 0 to 120 years
     * BMI: 10.0 to 80.0 kg/m2
     * HbA1c: 3.0% to 20.0%
     * Blood Glucose: 30.0 to 600.0 mg/dL
   - Blood Group: Must strictly match one of the 8 allowed values.
   - Phone Number: Validate using regex `/^\+?[0-9]{5,20}$/`.
   - File Uploads: Reject files > 15MB or not matching PDF/PNG/JPG before upload.
   - Coordinates: If latitude is provided, longitude is required (-90 to 90, -180 to 180).
2. Authorization Token Sanitization:
   - Forward Supabase JWT strictly in the `Authorization: Bearer <token>` HTTP header.
   - Never pass tokens, passwords, or hashes in URL query parameters or request bodies.
3. HTTP Status Code Handling:
   - 400 Bad Request: Display validation error message from `detail`.
   - 401 Unauthorized: Redirect to `/login`, clear cached user session.
   - 403 Forbidden: Display friendly warning toast (e.g. "Active FULL_ACCESS consent required for this action").
   - 404 Not Found: Display resource missing empty state.
   - 422 Unprocessable Entity: Parse FastAPI validation errors array `{ loc, msg, type }` into form field errors.
   - 503 Service Unavailable: Model artifact unavailable. Render graceful error banner:
     "Predictive AI service is currently initializing. Please retry in a moment."
