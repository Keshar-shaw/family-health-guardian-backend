1. EXECUTIVE SUMMARY & ARCHITECTURAL FOUNDATION
================================================================================
The Family Health Guardian frontend is an enterprise-grade, consent-driven, 
role-aware healthcare web application. It connects family members, patients, 
and designated guardians in a single privacy-first portal.

Core Architectural Tenets:
1. Security Identity (auth.uid()):
   - Authentication is performed via Supabase Auth.
   - The frontend forwards the Bearer JWT on every API request.
   - The backend enforces auth.uid() directly on every operation.
2. Zero-Trust Family Context:
   - The frontend never assumes permissions. Client-supplied family_member_id is 
     verified against ownership or active consent.
   - UI elements (Edit, Delete, Add Schedule, etc.) dynamically adapt based on 
     the user's permission level (READ_ONLY vs FULL_ACCESS).
3. Private Medical Storage:
   - Report files are never stored in PostgreSQL as blobs.
   - Uploads go via POST /medical-reports; downloads render secure, signed URLs 
     with 5-minute expiries.
4. Privacy-First Emergency SOS:
   - Location is captured ONLY during an explicit SOS trigger.
   - No continuous background tracking.
5. Tamper-Evident Audit Trail:
   - All healthcare operations (view, create, update, delete) are logged.
   - Passwords, tokens, and secrets are sanitized before persistence.

3. GLOBAL STATE & CONTEXT MANAGEMENT
================================================================================
The application requires 4 global providers:

1. AuthContext:
   - Stores current Supabase `user`, `session`, `accessToken`.
   - Handles login, signup, logout, session expiration refresh.
   - Profile state (`GET /profiles/me`).

2. FamilyContext:
   - `families`: List of families user belongs to (`GET /families`).
   - `activeFamily`: Currently selected family.
   - `activeFamilyMembers`: Members of active family.
   - `selectedMemberId`: Target member currently being viewed/managed.

3. NotificationContext:
   - Unread badge counter.
   - Periodic poll or Supabase Realtime channel for incoming alerts.
   - Toast trigger for urgent `EMERGENCY_SOS` or `MEDICINE_REMINDER`.

4. SOSContext:
   - Global floating emergency SOS trigger button.
   - Active emergency modal popup if an active SOS event exists in the family.

5. DETAILED SCREEN-BY-SCREEN SPECIFICATIONS
================================================================================

--------------------------------------------------------------------------------
5.1 Authentication & Onboarding (/login, /register)
--------------------------------------------------------------------------------
- Sign In (`/login`):
  * Email and Password fields.
  * Loading state and error toast on 401 invalid credentials.
  * Direct redirect to `/dashboard` upon successful login.
- Sign Up (`/register`):
  * Full Name, Email, Password, Confirm Password.
  * Password strength check (min 8 chars, mixed case, number, symbol).
  * Automatically creates user profile in Supabase.

--------------------------------------------------------------------------------
5.2 User Profile Management (/profile)
--------------------------------------------------------------------------------
- Endpoints: `GET /profiles/me`, `PUT /profiles/me`
- Fields: Full Name, Phone Number, Avatar URL.
- Features: View current details, edit in-place with instant validation.

--------------------------------------------------------------------------------
5.3 Family Hub & Member RBAC (/families, /families/:id)
--------------------------------------------------------------------------------
- Endpoints:
  * `GET /families`
  * `POST /families` (body: `{ name }`)
  * `GET /families/{id}`
  * `POST /families/{id}/members` (body: `{ user_id, role: "ADMIN" | "MEMBER" }`)
  * `DELETE /families/{id}/members/{user_id}`
- Features:
  * Family Switcher: Dropdown in the top navigation bar.
  * Member Roster: Shows member name, user ID, role badge (ADMIN in Indigo, MEMBER in Teal).
  * Add Member Modal: ADMINs can add members via user UUID.
  * Remove Member: ADMINs can remove any member; members can self-remove.

--------------------------------------------------------------------------------
5.4 Consent & Access Management (/consents)
--------------------------------------------------------------------------------
- Endpoints:
  * `GET /consents`
  * `POST /consents` (body: `{ grantee_id, family_id, permission_level }`)
  * `PATCH /consents/{id}` (body: `{ status: "ACTIVE" | "REVOKED" | "DENIED" }`)
- Permission Levels:
  * `READ_ONLY`: Guardian can view health vitals, medicines, reports.
  * `FULL_ACCESS`: Guardian can modify, create, and delete healthcare data.
- UI Tabs:
  * "My Granted Consents": Consents I have given to other family members. Actions: [Revoke], [Accept], [Deny].
  * "Consents Granted to Me": Members who granted me access to their records.
  * "Request Access" Modal: Select target family member and permission level requested.

--------------------------------------------------------------------------------
5.5 Health Records & Medical Summary (/health-records)
--------------------------------------------------------------------------------
- Endpoints:
  * `GET /health-records?family_member_id={id}`
  * `GET /health-records/{id}`
  * `POST /health-records`
  * `PUT /health-records/{id}`
  * `DELETE /health-records/{id}`
- Fields:
  * Blood Group: Restricted dropdown (`A+`, `A-`, `B+`, `B-`, `AB+`, `AB-`, `O+`, `O-`).
  * Allergies (Text area, e.g. "Peanuts, Penicillin").
  * Chronic Conditions (Text area, e.g. "Asthma, Hypertension").
  * Medical History (Text area, e.g. "Appendectomy in 2021").
  * Emergency Notes (Text area, urgent notes for paramedics).
- UI Logic:
  * Read-only view for users with `READ_ONLY` consent; edit buttons hidden or disabled.
  * Warning confirmation modal before deleting a record.

--------------------------------------------------------------------------------
5.6 Medicines & Prescriptions Catalog (/medicines)
--------------------------------------------------------------------------------
- Endpoints:
  * `GET /medicines?family_member_id={id}&is_active={bool}`
  * `GET /medicines/{id}`
  * `POST /medicines`
  * `PUT /medicines/{id}`
  * `DELETE /medicines/{id}`
- Fields:
  * Medicine Name (String, 1-100 chars, required).
  * Dosage (String, e.g., "500mg", required).
  * Frequency (String, e.g., "Twice daily with meals", required).
  * Start Date / End Date (Optional date pickers).
  * Instructions (Special notes, e.g. "Take after breakfast").
  * Active Status (Toggle button).
- UI Filter: Tab between "Active Medications" and "Past / Discontinued".

--------------------------------------------------------------------------------
5.7 Medicine Schedules & Intake Adherence Timeline (/medicines/schedule)
--------------------------------------------------------------------------------
- Endpoints:
  * `GET /medicine-schedules?medicine_id={id}`
  * `POST /medicine-schedules` (body: `{ medicine_id, scheduled_time, day_of_week, dose_quantity, reminder_enabled }`)
  * `GET /medicine-logs?family_member_id={id}&medicine_id={id}`
  * `POST /medicine-logs` (body: `{ medicine_id, schedule_id?, status: "TAKEN" | "MISSED" | "SKIPPED", taken_at?, notes? }`)
  * `PATCH /medicine-logs/{id}`
- Features:
  * Daily Intake Timeline: Morning, Afternoon, Evening, Night blocks.
  * One-Click Action Buttons on each dose:
    - [Mark as Taken] (Records exact taken_at timestamp).
    - [Skip Dose] (Prompts for optional reason).
    - [Mark Missed].
  * Adherence Scorecard: Visual percentage ring showing 7-day adherence rate.
  * Schedule Creator Modal: Time picker (HH:MM), day-of-week checkboxes, reminder toggle.

--------------------------------------------------------------------------------
5.8 Medical Reports & Storage Document Viewer (/medical-reports)
--------------------------------------------------------------------------------
- Endpoints:
  * `POST /medical-reports` (Multipart form-data: `file`, `family_member_id`, `report_type`, `report_date`, `description`)
  * `GET /medical-reports?family_member_id={id}&report_type={type}`
  * `GET /medical-reports/{id}`
  * `DELETE /medical-reports/{id}`
- Allowed File Types: PDF, PNG, JPG, JPEG (Client validation max 15MB).
- Report Types: `LAB_REPORT`, `PRESCRIPTION`, `IMAGING`, `DISCHARGE_SUMMARY`, `GENERAL`.
- UI Features:
  * Drag-and-drop upload zone with progress bar.
  * Grid of document preview cards with file size, report date, and uploader.
  * [View Document] button: Securely opens pre-signed Supabase Storage URL in new tab.
  * [Delete Report] button: Purges file from storage and metadata from database.

--------------------------------------------------------------------------------
5.9 Emergency Contacts & Priority Roster (/emergency-contacts)
--------------------------------------------------------------------------------
- Endpoints:
  * `GET /emergency-contacts?family_member_id={id}`
  * `POST /emergency-contacts`
  * `GET /emergency-contacts/{id}`
  * `PUT /emergency-contacts/{id}`
  * `DELETE /emergency-contacts/{id}`
- Fields:
  * Full Name (Required, 1-100 chars).
  * Relationship (e.g., Parent, Spouse, Physician, Neighbor).
  * Phone Number (Required, validated against regex `^\+?[0-9]{5,20}$`).
  * Email (Optional).
  * Priority Rank (Number 1 to 10; Rank 1 = Primary Contact).
  * Active Toggle (Include in emergency broadcasts).
- UI Feature: Contact cards sorted with primary contact pinned at top with prominent call icon.

--------------------------------------------------------------------------------
5.10 Emergency SOS Broadcast & GPS Location Capture (/emergency/sos)
--------------------------------------------------------------------------------
- Endpoints:
  * `POST /emergency/sos`
  * `GET /emergency/sos/{id}`
  * `PATCH /emergency/sos/{id}/status`
- Prominent Emergency Trigger:
  * Floating Red SOS Button available on every screen.
  * Hold-to-activate (3 seconds countdown) or double-tap confirmation to prevent accidental triggers.
  * HTML5 Geolocation API integration:
    - Extracts `latitude` (-90 to 90), `longitude` (-180 to 180), `accuracy` (meters), `timestamp`.
    - If GPS is disabled/denied, triggers alert immediately without location.
  * Optional quick text note (e.g. "Chest pain, need help").
- Active SOS Emergency Modal:
  * Real-time pop-up notification across all family members when an SOS is `TRIGGERED`.
  * Interactive Map (Leaflet / Mapbox) showing distressed member's coordinates and accuracy radius.
  * Quick Dial Emergency Contacts bar.
  * Status Control Actions:
    - [Acknowledge] -> Changes status to `ACKNOWLEDGED`.
    - [Mark Resolved] -> Prompts for resolution note, records `resolved_at`.
    - [Cancel False Alarm] -> Status `CANCELLED`.

--------------------------------------------------------------------------------
5.11 SOS Incident History & Filtering (/emergency/sos/history)
--------------------------------------------------------------------------------
- Endpoint:
  * `GET /emergency/sos/history?family_member_id={id}&status={status}&start_date={date}&end_date={date}&limit=50&offset=0`
- Features:
  * Reverse chronological log table (newest incident first).
  * Status Badges:
    - `TRIGGERED` (Flashing Red)
    - `ACKNOWLEDGED` (Amber)
    - `RESOLVED` (Green)
    - `CANCELLED` (Gray)
  * Filters: Status, Date Range picker, Family Member dropdown.
  * Detailed modal showing responder notes, incident duration, and GPS map snippet.

--------------------------------------------------------------------------------
5.12 Notification Center & Reminder Alerts (/notifications)
--------------------------------------------------------------------------------
- Endpoints:
  * `GET /notifications?status={status}&type={type}&limit=50&offset=0`
  * `PATCH /notifications/{id}/read`
- Notification Types:
  * `MEDICINE_REMINDER` (Icon: Pill / Medicine bottle)
  * `EMERGENCY_SOS` (Icon: Red siren / Alert triangle)
- Statuses: `PENDING`, `SENT`, `FAILED`, `READ`.
- UI Features:
  * Top navigation bell icon with unread count badge.
  * Dropdown preview + full-page feed at `/notifications`.
  * Click on notification marks it as `READ` and routes to relevant resource (e.g. to medicine schedule or SOS event).

--------------------------------------------------------------------------------
5.13 Immutable Audit Trail & Activity Logs (/audit-logs)
--------------------------------------------------------------------------------
- Endpoint:
  * `GET /audit-logs?family_id={id}&family_member_id={id}&action={action}&resource_type={type}&limit=50&offset=0`
- Tracked Actions:
  * `HEALTH_RECORD_CREATED`, `HEALTH_RECORD_VIEWED`, `HEALTH_RECORD_UPDATED`, `HEALTH_RECORD_DELETED`
  * `MEDICINE_CREATED`, `MEDICINE_UPDATED`
  * `MEDICAL_REPORT_UPLOADED`, `MEDICAL_REPORT_DELETED`
  * `SOS_TRIGGERED`, `SOS_STATUS_CHANGED`
  * `EMERGENCY_CONTACT_CHANGED`
- UI Display:
  * Audit table with Timestamp, Actor User ID, Action Badge, Target Entity, and Safe Context.
  * Reassurance banner: "Audit logs are strictly tamper-evident and immutable (protected by database trigger)."

--------------------------------------------------------------------------------
5.14 Diabetes ML Prediction & Risk Assessment (/diabetes-risk)
--------------------------------------------------------------------------------
- Endpoints:
  * `GET /predictions/diabetes/metadata` (Public metadata and clinical ranges)
  * `POST /predictions/diabetes` (Protected inference, requires JWT Bearer)
- Biometric Form Inputs:
  * `age` (Number, 0 to 120, float)
  * `gender` (Enum: "Male" | "Female" | "Other", case-insensitive)
  * `hypertension` (Boolean: Yes / No toggle)
  * `heart_disease` (Boolean: Yes / No toggle)
  * `smoking_history` (Enum: "never" | "current" | "former" | "ever" | "not current")
  * `bmi` (Number, 10.0 to 80.0, Body Mass Index with inline Height/Weight calculator helper)
  * `hba1c_level` (Number, 3.0 to 20.0%, normal < 5.7%, prediabetes 5.7 - 6.4%, diabetic >= 6.5%)
  * `blood_glucose_level` (Number, 30.0 to 600.0 mg/dL, normal fasting 70 - 99 mg/dL)
  * `family_id` (Optional string UUID: associate assessment with a specific family member)
  * `save_to_records` (Optional boolean: auto-persist assessment to health records)
- Preset Demonstration Profiles:
  * Healthy Preset (26yo, female, non-smoker, BMI 21.8, HbA1c 4.8, glucose 88)
  * Borderline Preset (48yo, male, former smoker, hypertension, BMI 27.8, HbA1c 6.0, glucose 125)
  * High Risk Preset (62yo, male, current smoker, heart disease, hypertension, BMI 33.4, HbA1c 7.8, glucose 175)
- Results & Clinical Risk Panel:
  * Risk Badge: `Low Risk` (Green) vs `High Risk` (Rose/Red)
  * Risk Percentage Gauge (0.0% to 100.0%)
  * Confidence Level Meter: `High Confidence`, `Moderate Confidence`, `Low Confidence (Borderline)`
  * Biometric Feature Summary card reviewing input values
  * Dynamic, Rule-Based Clinical Recommendations list tailored to specific risk factors:
    - HbA1c diabetic threshold alerts (>= 6.5%)
    - Pre-diabetes dietary intervention advice (5.7% - 6.4%)
    - Fasting glucose monitoring advice (>= 140 mg/dL)
    - BMI nutritional & exercise guidance (Overweight >= 25, Obese >= 30)
    - Cardiovascular dual lipid/glycemic coordination alerts
    - Microvascular smoking cessation counseling
  * Immutable Audit Log: Every inference execution is automatically logged into the audit trail.

================================================================================
8. FRONTEND SECURITY, VALIDATION & ERROR HANDLING
================================================================================
1. Client-Side Input Validation:
   - Blood Group: Must strictly match one of the 8 allowed values.
   - Phone Number: Validate using regex `/^\+?[0-9]{5,20}$/`.
   - File Uploads: Reject files > 15MB or not matching PDF/PNG/JPG before upload.
   - Coordinates: If latitude is provided, longitude is required (-90 to 90, -180 to 180).
   - Diabetes Biometrics: Validate numerical ranges before dispatch (age: 0-120, bmi: 10-80, hba1c: 3-20, glucose: 30-600).
2. Never send user emails for authorization:
   - Always rely on user UUIDs and Supabase Auth token payload `sub`.
3. Error Code Mapping:
   - 400 Bad Request: Display validation error message from `detail`.
   - 401 Unauthorized: Redirect to `/login`, clear cached user session.
   - 403 Forbidden: Display friendly warning toast (e.g. "Active FULL_ACCESS consent required for this action").
   - 404 Not Found: Display resource missing empty state.
   - 422 Unprocessable Entity: Parse FastAPI validation errors array `{ loc, msg, type }` into form field errors.
4. Secret Sanitization Guarantee:
   - Never send tokens or passwords in query params or request bodies.
   - Form inputs for sensitive data should clear on submit.
