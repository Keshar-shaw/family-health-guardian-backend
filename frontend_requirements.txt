1. EXECUTIVE ARCHITECTURAL SUMMARY & SECURITY
================================================================================
The Family Health Guardian frontend is an enterprise-grade, consent-driven, 
privacy-first healthcare management application. It connects patients, family
members, and healthcare guardians in a single authenticated portal.

Core Architectural Tenets:
1. Authentication & Identity:
   - Supabase Auth handles user signup, login, password resets, and session tokens.
   - Access tokens are signed using modern asymmetric ES256 (ECDSA) with project JWKS.
   - Every outgoing API request MUST attach: `Authorization: Bearer <access_token>`.
2. Zero-Trust Family Context & Consent:
   - Access to dependent family members requires active family membership and consent.
   - Roles: ADMIN (full family management), GUARDIAN (caregiver access), MEMBER (standard patient).
   - Consents: READ_ONLY vs FULL_ACCESS with statuses PENDING, ACTIVE, REVOKED, DENIED.
3. Private Medical Documents:
   - PDF/Image reports reside in Supabase Storage buckets.
   - The frontend requests short-lived 5-minute pre-signed URLs to display/download documents.
4. Privacy-First Emergency SOS:
   - Geolocation is requested ONLY on an intentional 3-second SOS button hold.
   - No continuous background tracking. Sends coordinates, address, and battery percentage.
5. Tri-Engine Machine Learning Suite:
   - Engine 1: Two-Tier Stacking Super Learner for Diabetes (Random Forest + HistGB + Logistic Regression meta-learner, 97.52% ROC-AUC).
   - Engine 2: Soft-Voting Blended Ensemble for Hypertension (13 physiological vitals).
   - Engine 3: Multi-Disease Symptom Diagnostic Model (Random Forest Multiclass covering 41 clinical diseases and 131 symptoms).
   - Automated Emergency Triage: High-risk predictions automatically alert designated guardians.
6. Immutable Audit Trail:
   - All healthcare operations (view, modify, delete, evaluate) generate an immutable audit log.

3. GLOBAL STATE & CONTEXT ARCHITECTURE
================================================================================
The frontend should expose three global contexts:

1. AuthContext:
   - `user`: Supabase User object (`id`, `email`, `user_metadata`)
   - `session`: Supabase Session (`access_token`, `refresh_token`, `expires_at`)
   - `profile`: User profile fetched from `GET /api/v1/profiles/me`
   - `signIn(email, password)`
   - `signUp(email, password, fullName)`
   - `signOut()`

2. FamilyContext:
   - `families`: List of families caller belongs to (`GET /api/v1/families`)
   - `activeFamily`: Currently selected Family object
   - `activeMember`: Currently selected Family Member (or self)
   - `callerRole`: Caller's role in active family (`ADMIN`, `GUARDIAN`, `MEMBER`)
   - `hasPermission(permission: 'READ_ONLY' | 'FULL_ACCESS')`: Consent validator

3. NotificationContext:
   - `unreadCount`: Integer count of unread alerts
   - `notifications`: Top recent alerts
   - `markAsRead(id)` / `markAllAsRead()`

```typescript

export type FamilyRole = 'ADMIN' | 'GUARDIAN' | 'MEMBER';

  id: string;
  family_id: string;
  user_id: string;
  role: FamilyRole;
  joined_at: string;
  profile?: UserProfile;
}

export interface Family {
  id: string;
  name: string;
  description: string | null;
  created_by: string;
  created_at: string;
  updated_at: string;
  members: FamilyMember[];

// --- Consents ---
export type ConsentPermission = 'READ_ONLY' | 'FULL_ACCESS';
export type ConsentStatus = 'PENDING' | 'ACTIVE' | 'REVOKED' | 'DENIED';

export interface Consent {
  id: string;
  granter_id: string;
  grantee_id: string;
  family_id: string;
  permission_level: ConsentPermission;
  status: ConsentStatus;
  notes: string | null;
  created_at: string;
  updated_at: string;

// --- ML Predictions & Symptoms ---
export interface FeatureImpact {
  feature_name: string;
  feature_value: string;
  impact_direction: 'HIGH_RISK_FACTOR' | 'MODERATE_RISK_FACTOR' | 'PROTECTIVE_FACTOR';
  importance_score: number;
  clinical_explanation: string;
}

export interface DiabetesPredictionResponse {
  prediction: number;
  risk_label: 'Low Risk' | 'High Risk';
  risk_probability: number;
  risk_percentage: number;
```
